Order By Injection

The ORDER BY clause can't use placeholders in most drivers. Here the sort column is concatenated directly — and that's all it takes.

Key Takeaways

Labs 01–03 all lived in the WHERE clause. Lab 04 shows that the injection surface doesn't end there — every part of the query that accepts input is a potential entry point.

01 — WHAT JUST HAPPENED

The catalog has two places where user input reaches the query: the category filter (quoted) and the sort column (unquoted). The application intended this: 

SELECT name, cost FROM products
WHERE category = 'tools'
ORDER BY name

But when you typed tools' UNION SELECT password, 1 FROM users -- in the category field: 

SELECT name, cost FROM products
WHERE category = 'tools' UNION SELECT password, 1 FROM users --'
ORDER BY name

The ' closes the string. The UNION adds a second result set — the users' passwords, arranged into the same two-column shape. The -- comments out the leftover quote and the ORDER BY. The page now prints passwords where product names used to be.

02 — WHY ORDER BY IS SPECIAL

In most drivers, WHERE values can be bound with placeholders (?). Column names and ORDER BY targets usually can't be — placeholders bind values, not identifiers. So developers often concatenate them instead, and that's the second injection point this lab demonstrates.

Here, the sort field lands raw at the tail of the query with no quotes around it. That means an attacker doesn't even need to break out of a string: whatever they type is the next token in the SQL statement.

The core insight: ORDER BY can reference any column of the table — including columns that aren't in the SELECT list. Sorting by a hidden column is a one-word injection.
03 — WHY IT'S DANGEROUS

Labs 01–03 taught you the payloads. Lab 04 teaches you the surface area: any unquoted piece of the query that accepts input is game, not just the ones wrapped in quotes.

  • Second injection point. Developers often parameterize WHERE and then forget that ORDER BY, LIMIT, column lists, and table names are still concatenated.
  • Hidden-column inference. Even without a UNION, sorting by a guessed column name tells you whether that column exists — a slow but effective schema probe.
  • Full UNION reach. Once the quoted WHERE value is broken, everything from Lab 03 applies: cross-table reads, one row per user, no error required.
  • Error-based fingerprinting. Referencing a table that doesn't exist produces an error that names it — a free map of what's there and what isn't.

This is the same bug as Lab 01 — string concatenation — expressed in a different part of the query. The lesson isn't "learn this payload"; it's "audit every concatenation point".

04 — THE THREE MISTAKES
  1. Concatenation beyond WHERE. The category was glued into the query as a string, and the sort column was glued in as a raw identifier. Both are injection points.
  2. Believing "it's just a sort". A column name feels less dangerous than a value, so it gets less scrutiny. In SQL, identifiers and values are both grammar — both must be controlled.
  3. Verbose errors. The app prints raw SQL errors back to the browser. That turns every failed guess into feedback.
05 — HOW TO FIX IT

Vulnerable:

const sql = "SELECT name, cost FROM products " +
            "WHERE category = '" + cat + "' " +
            "ORDER BY " + sort;

The WHERE value needs a placeholder — and the ORDER BY target can't be a placeholder at all, so it needs a whitelist: 

const SORTABLE = ["name", "cost", "category"];

const col = SORTABLE.includes(sort) ? sort : "name";

const sql = "SELECT name, cost FROM products " +
            "WHERE category = ? " +
            "ORDER BY " + col;

db.query(sql, [cat]);

Now the category is bound as a value (it can't break out of the string) and the sort column is guaranteed to be one of three known-safe identifiers. Anything else falls back to name. The injection has nowhere left to go.

Rule of thumb: values get parameters. Identifiers (column names, table names, sort direction) get allowlists. There is no third category — anything you're tempted to "escape" is one of these two in disguise.
