WAF Bypass

A naive blacklist WAF sits between you and the SQL engine. It strips UNION, SELECT, OR , and --. Every one of those has a documented bypass — because blacklists have to enumerate everything, and attackers only need one thing the list forgot.

PRODUCT SEARCH (BEHIND WAF)
CHALLENGES
01 — Bypass the UNION filterGet a UNION SELECT through with inline comments.
02 — Bypass the comment filterYou can't write --. Find another way to end the query.
03 — Bypass the OR filterForce the WHERE clause to be true without writing the letters O-R followed by whitespace.
View solutions
01 — Inline comments split keywords 
q: x' UN/**/ION SEL/**/ECT 1,2,3 --

The WAF strips the literal substrings UNION and SELECT. Adding a comment inside the keyword defeats a single-pass string replacement.

02 — # instead of -- 
q: x' UN/**/ION SEL/**/ECT 1,2,3 #
03 — || as logical OR 
q: ' || '1'='1

The filter only catches OR — it doesn't know || is also a logical operator in MySQL (and a string concatenation operator in most others). This is why real WAFs work on parsed tokens, not raw strings.
