Type Confusion & Implicit Casting

A field "looks numeric" because the column is numeric — so a validator only checks that. But the database engine happily coerces strings, hex literals, and scientific notation to numbers. Every one of those is a bypass a "just cast to int" fix misses.

AGE-GATED CONTENT

CHALLENGES
01 — Bypass with a non-numeric stringMySQL casts 'abc' to 0. Age gate falls open.
02 — Bypass a naive is_numeric()Hex literals (0x3138) and scientific notation (1e3) parse as integers in MySQL. Neither is "numeric" to a string-only check.
03 — Force the WHERE clause trueClassic 0 OR 1=1, but now you understand why the coercion is what makes 0 safe to inject next to.
